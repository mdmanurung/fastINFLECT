### 2. Make candidate selection explicit and checked

Use the same policy in `README.md` and `vignettes/fastINFLECT.Rmd`:

```r
candidate_method <- "inflection"
candidate <- result$selection[
  result$selection$method == candidate_method,
  ,
  drop = FALSE
]

if (nrow(candidate) != 1L) {
  stop("Expected exactly one inflection candidate.", call. = FALSE)
}
if (!isTRUE(candidate$partition_available[[1L]])) {
  stop(
    "Inspect `k_status`; if the candidate k is finite, add it to `set.i` and rerun.",
    call. = FALSE
  )
}

candidate_k <- candidate$k[[1L]]
key <- as.character(candidate_k)
if (!key %in% names(result$metaclustering.list)) {
  stop("The directly tested candidate partition is missing.", call. = FALSE)
}
```

Minor line wrapping or a more informative equivalent message is allowed. The
behavior is not negotiable: one named method, exactly one row, an available
partition, and an existing list key must all be checked before inspection.

State near the code that candidate rows are diagnostic summaries, not a
ranking, and that the example uses the directly tested inflection candidate
only to demonstrate inspection. It is not a default recommendation. Do not
describe coincident candidate values as independent confirmation.

### 3. Show the inspected partition and selected decision matrix

After obtaining the key, both guides must use the partition rather than leave
an unused assignment. The vignette must render a compact map and label counts,
for example:

```r
partition <- result$metaclustering.list[[key]]
partition_map <- data.frame(
  som_node = seq_along(partition),
  metacluster = unname(partition)
)
head(partition_map)
table(partition_map$metacluster)
```

The README may use the same compact display. Explain that positions are SOM
nodes and values are nominal metacluster labels; the table counts SOM nodes,
not events or cells; labels are not ordered scores and are not numerically
comparable across different `k` values. Call this an **inspected candidate
partition**, not a scientifically selected partition.

Add `criterion_pass` to the README result-field map. In both inspection code
paths, show `result$criterion_pass[[key]]` before `dip_pass`, `iqr_pass`, and
`combined_pass`. Explain:

- `criterion_pass[[key]]` is the matrix used to calculate `qc_pass_rate`;
- it equals the dip matrix for `uniform.test = "unimodality"`, the IQR matrix
  for `"spread"`, and the combined matrix for `"both"`;
- `TRUE` passed the recorded threshold, `FALSE` did not, and `NA` means that
  the selected decision was unavailable;
- component matrices and `failure_reason` remain necessary, especially because
  under `"both"` a definitive component failure can determine `FALSE` even if
  the other component is unresolved.

### 4. Interpret the rate with its counts

Display the selected row of `result$provenance$criterion_summary` for
`candidate_k`, retaining at least `k`, `criterion`, `passed`, `failed`,
`unresolved`, `total`, and `qc_pass_rate`.

README and vignette must agree on this bounded interpretation:

`qc_pass_rate` is `100 * passed / total` over the metacluster-by-marker matrix
selected by `uniform.test`; unresolved (`NA`) decisions remain in `total`.
Because `k`, cluster event counts, and test behavior change across candidates,
compare `passed`, `failed`, `unresolved`, and `total`. A higher rate means only
that a larger fraction passed. It does not imply fewer absolute failures or
that a partition is preferable or biologically valid.

Retain these interpretation boundaries:

- dip-test non-rejection means no detected multimodality at the recorded
  threshold, not proof of unimodality;
- IQR is a spread screen, not a unimodality test;
- per-pair thresholds are not multiplicity-controlled inference;
- increasing `k` changes group sizes and test behavior, so a rising curve is
  diagnostic rather than evidence that larger `k` is biologically better.

Keep prose compact and task-oriented; do not turn the vignette into a methods
essay.
